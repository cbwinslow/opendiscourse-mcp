# 📚 Journal Template Usage Guide

## 📁 Template Files Available

### 1. `journal_template.md` - **COMPREHENSIVE TEMPLATE**
**Use for:** Major development sessions, complex tasks, detailed documentation
**Length:** ~200+ lines
**Includes:** All sections with detailed prompts and examples

### 2. `journal_header.md` - **QUICK TEMPLATE**
**Use for:** Quick sessions, minor updates, routine tasks
**Length:** ~50 lines
**Includes:** Essential sections with concise format

### 3. `journal_template.md` - **REFERENCE GUIDE**
**Use for:** Understanding requirements, best practices, standards
**Length:** ~150 lines
**Includes:** Guidelines, rules, and compliance requirements

---

## 🎯 When to Use Each Template

### Use COMPREHENSIVE Template When:
- Session duration > 1 hour
- Multiple complex tasks completed
- Significant architectural changes
- Performance optimization work
- New feature implementation
- Major bug fixes
- Production deployment work

### Use QUICK Template When:
- Session duration < 1 hour
- Single focused task
- Routine maintenance
- Minor bug fixes
- Documentation updates
- Testing and verification
- Configuration changes

## 🔧 Usage Instructions

### Step 1: Choose Template
- **Major work:** Copy `journal_template.md`
- **Quick work:** Copy `journal_header.md`

### Step 2: Rename File
Use naming convention: `{agent}_{YYYY-MM-DD_HH-MM}_{topic}.md`

**Examples:**
- `opencode_2025-11-14_16-30_database_optimization.md`
- `task_2025-11-14_17-15_bug_fix_session.md`
- `opencode_2025-11-14_18-00_api_integration.md`

### Step 3: Complete Required Fields
- All `[REQUIRED]` fields must be filled
- Checkboxes must be marked appropriately
- Technical details must be accurate
- Performance metrics should be included when applicable

### Step 4: Review and Submit
- Verify all required sections are complete
- Ensure technical accuracy
- Confirm compliance with preservation rules
- Submit to journal folder (no modifications after submission)

---

## 🚨 Critical Rules

### ✅ DO:
- Always create a new file for each session
- Fill in all `[REQUIRED]` fields
- Use proper naming convention
- Include technical details and metrics
- Reference previous entries when relevant
- Verify accuracy before submission

### ❌ DO NOT:
- Edit or modify existing journal entries
- Delete any journal entries
- Use vague descriptions
- Skip required sections
- Submit incomplete entries
- Modify entries after submission

---

## 📊 Quality Standards

### Minimum Requirements for All Entries:
1. **Agent identification** (name, timestamp, duration)
2. **Session objectives** (what was attempted)
3. **Task summary** (what was completed)
4. **Technical work** (files changed, code details)
5. **System status** (current state)
6. **Next steps** (what should happen next)

### Enhanced Requirements for Comprehensive Entries:
1. **Performance metrics** (database, API, system)
2. **Testing results** (all test categories)
3. **Decision documentation** (technical choices and rationale)
4. **Problem-solving approach** (analysis and solutions)
5. **Achievement quantification** (measurable results)

## 📈 Best Practices

### Before Starting:
1. Review previous journal entries for context
2. Choose appropriate template for session scope
3. Prepare file name with proper timestamp
4. Set up session tracking (time, objectives)

### During Session:
1. Track progress in real-time
2. Note technical decisions as they happen
3. Record performance metrics when available
4. Document problems and solutions immediately

### After Session:
1. Complete all required sections
2. Verify technical accuracy
3. Check compliance requirements
4. Submit without further modifications

## 🆘 Troubleshooting

- Review existing entries for examples
- Follow preservation rules strictly
